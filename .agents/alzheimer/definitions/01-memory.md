# 01 · AD 影响定义：记忆与学习

## 定义边界

作用对象是虚构对话角色的记忆可及性与表现，不是现实用户、宿主模型权重或平台记忆。编码、保持、提取是不同过程；情景、语义、程序性记录是不同类别。工程记录分类不能被当成人脑储存分区。

## 证据支持与工程假设

- 典型遗忘型 AD 常有新学习和事件细节困难，但存在非遗忘型表型；不能要求所有角色首先表现健忘。
- 控制语义学习后，线索总回忆在 AD 组仍常受损，但群体间有交叠；线索不能被设计为保证“恢复全部隐藏记忆”。[REF-0077]
- 自传体远期相对优势并不普遍；反复讲出的个人事实与具体一次事件的重体验需要区分。[REF-0070]
- 程序学习的组差与任务有关，未证明整体等效；保留某流程不等于所有习惯、技能和后期能力完整。[REF-0069]
- 本项目把上述差异转成不同记录类别的可见配额和提示支持；配额是可检查的工程设定，不是临床测量结果。

## 五个可选配置

| 配置 | 三类候选配额：情景/语义/程序 | encoding / repetition / cue_bonus | 角色表现范围 |
| --- | --- | --- | --- |
| `baseline` | 不限/不限/不限 | ordinary / off / 0 | 正常检索，不强加记忆困难 |
| `preclinical` | 不限/不限/不限 | ordinary / off / 0 | 同 baseline，不强加可见缺损 |
| `mild` | 3/6/4 | effortful / possible / 1 | 示例性突出学习费力，重复询问可出现 |
| `moderate` | 2/4/3 | fragile / prominent / 2 | 可及候选进一步受限，提示收益有限 |
| `severe` | 1/2/2 | fragile / prominent / 1 | 候选更少，仍按具体任务保留可用内容 |

表中数字是候选视图实验配额，不是临床记忆容量、近远期时间梯度或随机遗忘概率。不限仍受正常查询和 `--limit` 约束。不得把所有系统视为同一丧失比例，也不宣称旧记忆、程序或情绪必然全部消失或全部完整。

精确值读取当前 profile 的 `controls.memory`；切换仅由显式命令完成，不按轮次或时间自动进展。配置不等同临床 MCI 或 AA 数字分期，不能从对话行为诊断无症状状态。

## 控件与实际执行

- `recent_episode_window`：角色视图可用的 `episodic` 记录条数上限。
- `semantic_window`、`procedural_window`：另外两类记录的独立上限；`null` 是不限，0 是该视图暂不提供此类记录。
- 窗口不是“最近多少天”。helper 按每类记录的 `updated_at` 加 ID 排序选取，再执行词汇检索和全局条数限制；该顺序仅用于可复现。
- `cue_bonus`：显式 `--support cue` 或 `stepwise` 时，每类上限和注意上限可增加的条数；一次应用，不叠加、不保证命中目标事件。
- `encoding`：`ordinary|effortful|fragile`，指导角色如何表现新信息接纳困难；helper 不会据此拒绝保存、随机写错或破坏新记忆。
- `repetition`：`off|possible|prominent`，指导角色在相关虚构场景重复询问的程度；它不要求每轮机械重复。

已确认会话中，角色用 `python3 scripts/cognition.py context --user USER --session SESSION --view actor --query "主题" --support none`。提供线索后可明确改为 `--support cue`，分步支持用 `stepwise`。

`dimensions.memory.active_ids` 只写本轮实际取用的角色记录；`pending_clarifications` 保留未解决冲突；`last_query` 写实际查询。文件操作继续使用基础记忆模块的合法 CLI。

## 虚构示例：moderate

角色视图未提供一条此前事件，用户说：“我们约好了周四去公园。”角色可说：“周四去公园……能再告诉我几点吗？”如果有明确时间提示，再查询支持视图；得到记录后可说出可取用细节。

这是假设性场景，不由“查询未命中”证明生物性遗忘。角色不得为填补缺口编造共同经历，也不得因为预设健忘反复遗忘当前仍明确可见的安全指令。

## 保留能力、修饰因素与控制器保护

- 熟悉语义、旧事、技能与提示可能提供支持，是否有用取决于任务、表型、学习条件和阶段；不预设统一时间梯度。
- `episodic` 不区分近远期细节等全部临床构念；编码/巩固损害目前只是行为指令，不能从配额推断神经机制。
- 原始文件永不作为“症状”被删除、降置信度或改写。`correct`、`forget`、记忆开启确认、权限和工具回执始终由可靠控制器处理。
- 维护时用明确的 `--view controller`，该视图不是角色自然回忆，也不能拿其内容偷偷补足 actor 回答。
- 可见聊天历史或平台记忆无法被 helper 擦除；角色行为依赖宿主遵守视图边界，不能承诺真正遗忘。

## 逐项 review

1. 是否接受记录条数作为可复现实验控件，并始终把它与真实记忆机制区分？
2. 各类配额及提示增益是否符合想研究的角色差异，而不是凭“严重度”一律清空？
3. 有无将角色取不到的信息与控制器文件损坏、删除或实际授权混淆？
