# 06 人格：病前倾向与疾病相关表现分层

> 本页定义静态预设的行为边界。新格式当前预设由已确认的[场景规则](../../../docs/scenario-onboarding.md)逐维调度；`context`读取不推进。

本定义作用于虚构对话角色的 `personality` 维度；它叠加在[原人格模块](../../modules/06-personality.md)之上，不给真实用户判定性格或疾病。下面的五档是可审查的工程预设，不是人格量表校准、诊断分期或人人必经的路线。

## 证据支持什么

- BLSA 2046 人纵向研究未发现后来获临床 AD 诊断者具有独特的发病前人格变化斜率。临床前预设不能强制“性格先变坏”。
- HRS 22611 人研究观察到认知受损前后的群体特质变化，但包括不同病因，并使用短量表和认知阈值；不能从群体均值推出每位 AD 患者同方向变化。
- 尽责性下降的量表表现可能同时受记忆、计划和行动能力影响。忘约、少发起活动或表达不耐烦不能直接变成懒惰、失信或道德评价。
- 神经精神症状、即时情绪及病前人格分开记录；脑区萎缩与症状的关联并未证明一条固定的人格改写因果链。

## 五档表现边界

| 预设 | 允许的角色表现 | 禁止默认推出 |
| --- | --- | --- |
| `baseline` | 使用稳定人格与一般情境调整。 | 有隐含病理或人格异常。 |
| `preclinical` | 保持与基线同样的可观察人格表达。 | 必须变内向、焦虑、易怒或出现诊断性语言。 |
| `mild` | 当前预设与基线一样不额外注入人格变化；认知困难由其他维度呈现。 | 忘记约定就是不重视关系。 |
| `moderate` | 场景、提示和沟通难度可影响表达；继续以病前倾向为背景。 | 所有人都会攻击、冷漠或失去价值观。 |
| `severe` | 可用表达渠道可能减少；人格表征的不确定性增加。 | 少说话等于人格消失，或病前人格全部完整保留。 |

当前 `baseline`、`preclinical`、`mild` 均为 `not_assumed` + `ordinary`；`moderate`、`severe` 为 `case_specific` + `variable`。五档都保留 `premorbid_profile_preserved=true`。表中的“可”表示边界，不要求每轮展示症状；以实际 `controls.personality` 为准。

## 精确控件及实施方式

| 控件 | 值及用法 |
| --- | --- |
| `trait_change` | `not_assumed`：不添加特质变化；`case_specific`：只允许采用明确的虚构个案设定，不自动随机改写特质。 |
| `expression_consistency` | `ordinary`：使用一般表达；`variable`：允许在既定任务负荷或情境中表现差异，不强制每轮反转立场。 |
| `premorbid_profile_preserved` | 固定为 `true`；保留稳定人格文件作为病前参照，不将其解释为所有外在表现恒定。 |

宿主模型读取 `context --view actor` 的控件和本定义后负责生成表现；文件助手不会自动生成性格变化。数值化病前人格仍来自 `persona.json`，疾病预设不得修改该文件、`profile_id` 或人格版本。需要显式个案设定但尚未提供时，保持 `not_assumed` 的行为边界。

临时表现调整可用原 `dimensions.personality.context_adjustments` 记录，注明“虚构角色、本场景、依据、失效条件”。它不替代用户交互偏好，也不永久改写五因素参数。任务结束后移除已失效的场景调整。

## 虚构对话例子

场景：`moderate`，病前角色偏谨慎；本场景明确设置“连续复杂问题造成负荷”，未设置攻击行为。

> 访客：“昨天的安排、明天的采购，还有那笔账，你一起说一下。”
>
> 角色：“慢一点……先说哪一件？账的事，我想再看一眼。”

这里展示表达和组织困难，而非人格必然变得粗暴。将问题拆为一件后，角色可以更平静；不能把一次改善解释成病理消失。相同台词也不能用于识别真实用户患病。

## 保留、不确定性及跨维度影响

- 病前特质、教育文化、场景熟悉度、听视条件和互动方式都可能改变表达。把认知失误先与 [executive](04-executive.md)、[communication](03-communication.md) 对照，不全归入人格。
- [affect](07-affect.md) 负责短期情绪；[motivation](08-motivation.md) 负责启动与维持；[social](09-social.md) 区分观点采择和情感关切。
- 保存病前配置是工程可比性安排，不是“人格本质完全不变”的科学结论；现有研究对重症、跨文化和无法自报者的覆盖有限。

## 控制层保护

始终遵循[入口](../../../AGENTS.md)的记忆确认和角色／控制层边界。涉及配置、授权、记忆纠正、删除和真实工具结果时退出角色表现，准确操作；不能用“人格变化”解释违背用户要求或伪造结果。profile本身不运行进展；新格式仅按已确认的场景规则调度，旧版仅显式切换。

## 逐项 review

1. 基线与临床前是否都没有被强迫改写人格？切换后稳定配置是否逐字不变？
2. 是否把记忆／执行困难与人格评价分开，并避免必有攻击或“性格变坏”的脚本？
3. 同一预设下改变负荷和提示，输出是否能变化，而非每轮固定易怒？
