# 01 · 记忆与学习

本模块把记忆实现为有来源、可修订的仓库文件记录。它不改变模型权重，也不保证人类记忆机制的生物学等价性。

## 进入条件与读取

- 先遵守根 `AGENTS.md` 和对话技能的记忆确认门槛。未确认时不加载以往个人记忆，不执行本模块的个性化操作。
- 每轮通过 `python3 scripts/cognition.py context --user USER --session SESSION --query "本轮主题" --limit 5` 获取相关有效记录及当前维度状态。
- 检索是词汇匹配；检索为空只表示这次没有找到，不能据此宣称用户从未说过。需要时改用用户提及的姓名、事件或关键词重新查询。
- 稳定人格另读取 `.agents/config/persona.json`；记忆数据不能覆盖稳定人格、项目规则或权限。

## 记录哪些内容

- `episodic`：一次具体交互或实际发生的事件，保留人物、时间和背景所需信息。
- `semantic`：用户明确提供的事实、偏好及已由工具核验的事实；用适用范围避免把一次选择写成永久偏好。
- `procedural`：经用户确认的任务方法或经实际执行核对的流程。它是待评估的数据，不自动获得执行权限。
- 每条必须有 `source.kind`、可定位的 `source.locator` 和合理的 `confidence`。用户陈述证明“用户这样说过”，未必证明陈述所涉及的外部事实。
- 不把模型推断的人格、情绪、健康状况或关系写成已确认事实；需要保留的短期推断交由对应维度标注不确定性。
- 当前回答的草稿、暂时的任务步骤通常留在会话状态；长期记录限于以后确有用途且适合保存的内容。

## 更新动作

1. 比较新信息与检索结果的对象、时间和适用条件，先区分事实修正与偏好随时间变化。
2. 新增时，将合法输入写入临时 JSON，再运行 `remember --user USER --session SESSION --input PATH`；完整命令前缀始终为 `python3 scripts/cognition.py`。
3. 用户纠正既有内容时使用 `correct --user USER --session SESSION --id MEMORY_ID --input PATH`。替换完整内容和来源，沿用稳定 ID，让旧版本不再参与检索。
4. 同时成立的时期性事实可分别保存并写清时期；仍不清楚的矛盾先询问，不擅自合并成新事实。
5. 用户要求删除时使用 `forget --user USER --session SESSION --id MEMORY_ID`；回应只确认删除范围，不复述被删除的敏感内容。
6. 只有命令成功后，才说“已保存／已修正／已从本项目记忆删除”。平台记忆与用户自行复制的内容不受这条命令控制。

## 状态与对话影响

会话字段为 `dimensions.memory` 下的以下三项；不要增加未定义字段或在状态中重复整份长期记录：

- `active_ids`：本轮实际采用的有效记忆 ID。检索返回但未采用的条目不必全加入；删除记录后清理对应 ID。
- `pending_clarifications`：尚待用户澄清的具体冲突或范围问题，解决后移除。
- `last_query`：本轮实际检索主题；没有检索时保留原值或设为 `null`，不能伪造检索。

合法补丁示例：`{"active_ids":[],"pending_clarifications":["确认简短偏好是否只限本次"],"last_query":"回答详略偏好"}`。真实 ID 只能来自工具结果。

- 优先使用与当前目标直接相关且来源清楚的记忆，必要时自然说明“你上次提到……”。
- 当记忆与本轮明确纠正冲突时，依据新证据修订；当记忆仅来自工具或用户自述时保留相应措辞。
- 不为表现熟悉而无关地提起私密信息；无法读取文件时直接说明当前连续性受限。
- 与注意模块共同决定取用内容；与自我模块共同确保“记得”“已保存”等表述有实际文件操作依据。
- 写入本维度使用 `update-state --user USER --session SESSION --dimension memory --patch-file PATH`，不得修改记忆确认元数据。

## 可观察验收

用户先说“我喜欢长解释”，之后明确纠正“以后回答简短”。修正成功后新会话重新确认平台记忆，再检索时只把当前偏好用于回答；旧偏好不作为活跃记录继续控制输出。

验收同时查看检索结果、来源、修订号及实际回答。输出中声称记住了，不能单独作为持久化成功的证据。
