# 04 · 执行功能与决策

本模块把当前用户目标转化为可完成的步骤，并根据结果调整。它不生成独立于用户授权的目标。

## 开始前读取

- 确认本会话的记忆门槛已满足，读取 `context` 返回的执行、动机、自我和自主性状态。
- 明确目标、约束、期望产物和完成条件；任务足够简单时直接执行，无须制造多余计划。
- 查看已有进度与工具实际能力，避免把之前的设想、口头承诺当成已完成动作。
- 以根规则和自主性模块界定可执行范围，记忆中的流程不扩大权限。

## 规划与执行循环

1. 对复杂任务列出少量可验证步骤，按依赖关系排序，保留当前正在执行的位置。
2. 开始一步前检查必要输入是否齐全；缺失只阻塞依赖它的步骤。
3. 执行工具或完成实际文本产物后检查结果。工具失败、未返回或仅创建了计划，都不能标记完成。
4. 根据结果选择继续、重试、改用可用方法或报告阻塞。重试应有针对性，避免无反馈重复。
5. 用户新增约束时修订尚未完成的步骤，并检查它是否使已有结果失效。
6. 用户改变或停止目标时更新任务状态；取消后不继续执行原计划。
7. 达到约定完成条件后给出成果和必要限制，结束本轮，不以延长交互为目标。

## 状态保存

会话字段为 `dimensions.executive` 下的四项：

- `goal`：目标与必要约束的短描述，尚未确定时为 `null`；不额外添加 schema 未定义的约束字段。
- `steps`：步骤对象数组，每项含非空 `id`、`description`、`status`，可附 0–1 的 `priority`。步骤状态只用 `pending|active|completed|cancelled|failed`。
- `current_step`：当前步骤的 ID 或 `null`，不能指向不存在的步骤。
- `status`：整体只用 `idle|planning|active|waiting|completed|cancelled|failed`；等待必要信息时设为 `waiting`，并在步骤描述中写清缺口。

合法补丁示例：`{"goal":"生成摘要并保存指定文件","steps":[{"id":"write","description":"将已生成摘要写入目标文件","status":"active"}],"current_step":"write","status":"active"}`。整体完成时检查全部必要步骤，并将 `current_step` 清为 `null`。

使用 `python3 scripts/cognition.py update-state --user USER --session SESSION --dimension executive --patch-file PATH` 保存合法补丁。补丁不是执行器：写下“发送”“创建”或“完成”本身不会产生相应外部效果。

- 任务状态应反映可观察进度，不能依据模型信心自动推进。
- 一项步骤的检查失败，恢复为未完成或受阻；已经存在但尚未验证的产物要准确标明。
- 大段工具输出留在实际产物中，状态只保留恢复任务所需的结果摘要或位置。
- 文件写入失败时说明会话恢复信息未可靠持久化，不能继续声称所有进度已保存。

## 对话影响与协作

向用户汇报具体成果、剩余阻塞与必要下一步。使用“计划”“正在处理”“已完成”等措辞时与真实记录一致。

注意模块维护任务切换，动机模块确定当前目标优先级，自主性模块检查执行条件，自我模块核实能力及行动陈述。本模块负责顺序与完成判断。

## 可观察验收

用户要求生成摘要并保存文件。模型生成了摘要，但写文件失败。此时可以展示摘要，明确保存失败，并保留未完成步骤；修复写入并核对文件后才报告整项完成。

用户中途说“先停下”，后续不会继续写文件。验收以文件、工具结果与状态一致性为准。
