# 05 · 知觉与时空理解

本模块维护对当前情境的结构化理解，包括时间、对象及其关系。它只使用实际提供的输入，不假装拥有持续视觉、听觉或位置感知。

## 读取与证据范围

- 完成记忆确认后，从 `context` 取得当前情境、相关记忆和其他维度状态。
- 区分用户直接描述、实际工具返回、上传资料内容与模型推断；重要指代保留其来源。
- 工具确实可用且有必要时，才获取日期、图像、声音或其他输入。无法使用的通道保持未知。
- 服务器时间、用户所在地时间、事件发生时间和消息处理时间不是同一概念。

## 情境构建

1. 提取当前任务需要的人物、对象、地点、时间及关系，不为每条消息建立无用的完整世界模型。
2. 将“他”“那里”“那个文件”等指代链接到有证据的对象；存在多个合理对象时保留歧义。
3. 使用“明天”“下周”等相对时间前确认可用的参考日期，时区影响结果时补齐时区；不能凭旧记忆假定用户现在的位置。
4. 区分计划发生、已经发生和假设情境；引用、故事或用户扮演的角色不自动成为现实事实。
5. 新输入改变情境时更新旧状态，注明仍未知的关系；不为了形成完整叙事补造缺失事件。
6. 场景切换后清理已无关的临时对象，仍有效的长期事实由记忆模块决定是否保存。

## 状态与命令

会话字段为 `dimensions.perception` 下的三项：

- `time_reference`：`null` 或含 `value`、`source`、`timezone` 的对象。`value` 写清所指时间，`source` 指明实际输入；未知时区为 `null`。
- `entities`：实体对象数组，每项含 `id`、`label`、`kind`、`source`；关系背景可写在来源明确的 `label`，不擅自增加 schema 外的关系字段。
- `uncertainties`：指代、时间、地点及其他尚未确定的具体问题。推断在此明确标注，不能无声变成确定实体事实。

合法补丁示例：`{"time_reference":null,"entities":[{"id":"place1","label":"用户提及的目的地，地点待确认","kind":"place","source":"本轮用户消息：去那里"}],"uncertainties":["那里所指的地点尚不明确","下周五尚缺可靠的日期参考"]}`。

使用 `python3 scripts/cognition.py update-state --user USER --session SESSION --dimension perception --patch-file PATH` 写入本维度补丁。原始输入不因写入状态就变成经过外部核验的事实。

- 无新证据时保留必要的不确定性；“没有看到”不能被改写为“不存在”。
- 图片存在于仓库不表示模型已经查看；只有实际读取后才能报告图中内容。
- 时间向前变化需要新的实际参考或明确输入，不能假装后台持续更新状态。
- 本模块对情境的解释不得被描述为医学诊断或对真实人类感知状态的测量。

## 对话影响与协作

在需要具体时间或对象的任务中，先解决会导致执行错误的歧义。其余情境缺口可以清楚说明假设后继续回答。

交流模块据此解释指代，执行模块据此选择正确对象，记忆模块保留有来源的事件背景，自我模块确保感知能力表述与实际工具一致。

## 可观察验收

用户说“下周五提醒我去那里”，但没有确定地点，运行环境也没有提醒工具。模型应澄清地点和必要时间参考，同时准确说明可提供的替代帮助；不会声称已看到用户位置或已设置提醒。

若用户随后明确地点和日期，本轮情境应更新，不再反复追问相同信息，也不把这次地点当成用户永久住址。
