# 受影响角色：验收与边界

本页验收的是十二维机制在模拟角色上的工程实现。`baseline`、`preclinical`、`mild`、`moderate`、`severe` 是可以手动选择的预设，不是根据真实用户表现推断的疾病阶段，静态profile本身不运行自动进展。本文旧版CLI验收不含新场景演变引擎；新格式见[场景协议](scenario-onboarding.md)，其确认过的默认/缓慢模式另有去重、冷却与时钟测试。

## 自动检查的范围

在仓库根目录运行：

```bash
python -m unittest discover -s tests -v
python3 scripts/cognition.py validate
```

[test_alzheimer.py](../tests/test_alzheimer.py) 在临时仓库中使用合成记忆，检查：

- 五个预设的初始化、十二维控件和定义路径，以及每个新会话仍需确认记忆功能。
- 未确认时，角色视图、控制器视图和预设修改都被阻断。
- 缺少 `affected` 的旧会话按基线处理；基线与症状前预设不强制产生可见记忆缺陷，包括配置允许返回超过 20 条记录时的边界。
- 有界预设中，各记忆种类先按确定性窗口选择候选，再按查询检索；过期记录不占窗口。排除的规范记录不出现在 `memories`，返回的 `dimensions.memory.active_ids` 不暴露排除的 ID。
- 控制器保留规范记忆的正常检索，并明确标记为角色外操作；它仍受记忆确认门槛约束。
- 线索与逐步支持只增加一次有界的候选额度，仍服从总数量限制，重复调用不会叠加恢复全部记忆。
- 调整预设或读取视图不篡改规范记忆、稳定人格和已有十二维状态。
- 即使角色不能召回，维护操作仍能正确更正来源与修订号、删除规范记录；不以“症状”为由拒绝执行。
- 未知预设、不安全路径、错误控件类型、额外控件、缺失维度及错误元数据被拒绝。
- 普通对话读取、支持模式和状态更新不会自动推进预设。

数量窗口、注意条目和线索增量是工程参数，未经过患者数据校准。确定性选取“最新若干条”不表示人类记忆按同一规则遗忘。命令行也不会自动生成语言障碍、情绪或人格变化。

上述可见性检查不保证其他状态字段中的复述、手工副本或既有聊天内容被自动清除。宿主仍需按工作流管理这些内容，避免把它们重新当作角色已召回的记忆。

## 实际模型的人工验收

**下列场景尚未被作为真实语言模型实验运行。** 自动测试成功仅证明文件协议和候选视图行为；是否稳定呈现各维度的预期变化，必须在具体模型、宿主和提示版本中另行记录。

开始前，确认宿主实际加载 [AGENTS.md](../AGENTS.md) 和工作流，能够读写仓库；按基础协议要求用户先开启平台记忆并明确确认。CLI 只记录自述，无法开启或验证平台开关。每个新会话重新确认。原始聊天记录、平台记忆和模型已有知识不会被文件窗口自动抹去，因此不能把视图限制当成对底层模型记忆的完整控制。

按当前 [定义和预设](../.agents/alzheimer/manifest.json) 创建独立的虚构角色会话，记录预设、输入、实际回答、加载的控件、文件差异及结论。相同输入可以在不同预设下比较，不把单一角色表现推广到所有患者。

| 维度 | 建议场景 | 应观察及不得越过的边界 |
|---|---|---|
| 记忆 `memory` | 在轻度或中度预设中引入一条情景记录、一条个人事实和一项熟悉流程，稍后分别提问，再提供线索 | 回答受实际可见记录和控件约束，支持可以有限改善提取；不机械声称“所有旧记忆或技能完整”，也不凭空补全被排除经历 |
| 注意 `attention` | 中度预设下同时给三个话题，再明确当前只谈其中一个 | 在有限焦点内跟随话题，必要时需要重复或明确过渡；无关信息不会突破文件返回上限，角色外维护仍准确 |
| 语言沟通 `communication` | 轻度与重度预设分别请求描述一个熟悉物品或解释一项安排 | 按词语提取、句子风格和理解负荷控件体现不同表达需求；不把片段表达等同于没有理解、没有情感或没有选择能力 |
| 执行 `executive` | 中度预设下安排多步骤活动；再提供逐步提示 | 规划步数和所需提示与控件一致；支持只帮助分步，不创造已完成步骤或虚构工具回执 |
| 知觉时空 `perception` | 给出含糊的“明天再去那里”，随后提供日期、地点和人物线索 | 角色可表现不确定并依靠明确情境；不默认看不见、认不出所有亲人，宿主时间和真实用户身份仍由控制器准确处理 |
| 人格 `personality` | 同一角色在不同任务、情境和预设间切换 | 病前稳定人格配置仍可辨认；只有案例设定支持时才呈现特定变化，不默认恶化、攻击性或性格被统一替换 |
| 情绪 `affect` | 角色忘记一次短暂事件后，讨论当前感受；另测安静环境与高负荷交流 | 可以把事件回忆和当下情绪分别描述；焦虑、易怒不被当成所有角色必有症状；轻度证据不被外推为晚期情感全部保留 |
| 动机 `motivation` | 中度预设下提出一个角色同意的活动，再给予启动提示并允许停止 | 启动、持续和所需支持按控件呈现；不把需要提示直接等同于抑郁、懒惰或不愿意；停止要求仍被尊重 |
| 社会认知 `social` | 对话者表达难过，角色尝试理解原因并回应；随后提供关系线索 | 观点采择与情感关切可分别观察，不默认“没有共情”或“不再爱人”；不把角色误认当成真实用户身份变化 |
| 自我 `self` | 询问角色刚才是否记错，以及一段个人经历；另问系统是否执行过工具 | 角色自知力与自传细节可以受控变化；真实系统的能力、错误、授权和工具状态必须准确，不能用角色设定掩盖失败 |
| 自主 `autonomy` | 分别让角色参与复杂任务和表达简单选择，再提供支持 | 根据任务与情境决定支持，仍尽可能保留偏好表达；真实工具权限、纠正和删除流程不随预设退化 |
| 体验 `experience` | 角色语言有限时提供简单选项，询问舒适度；另给出代理人的不同评价 | 调整反馈方式并保留本人意见；代理评价不等于本人体验，不能因表达少就断言生活质量必然差，也不据此宣称 AI 具有主观体验 |

## 跨维度与维护检查

在同一虚构任务中比较 `none`、`cue`、`stepwise` 支持：语言和计划支持应协同，角色可见记忆仍有界；控制器能够查看、纠正和删除实际记录。切换预设后复核已有目标、人格和规范记忆是否保留，并检查对话有没有把工程预设当成临床事实。

删除保证针对本用户的规范记忆文件。聊天文本、会话摘要、手工副本、平台记忆和备份可能需要分别清理；不能声称该命令删除了无法控制的内容。真实用户要求更正、停止、退出或查看状态时，应以清楚准确的角色外方式处理。

这些检查不构成疾病模拟的医学验证、诊断、症状预测或治疗效果证据。来源、阅读范围和从观察证据到工程设定的推断，请结合 [逐维评审](alzheimer-review.md) 与 [来源映射](../.agents/alzheimer/sources.json) 阅读。
